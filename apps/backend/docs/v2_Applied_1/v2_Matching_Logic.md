# 支援制度マッチングロジック v2：減点方式への刷新

本ドキュメントは、v2バックエンド拡張におけるマッチングロジックの設計方針を定義する。

既存の「加点方式」から、満点からの「減点方式」へ刷新することで、ユーザーに対して「なぜ100点ではないのか（何を確認すべきか）」をより明確に提示することを目的とする。

## 1. 基本方針

1.  **100点満点からのスタート**
    *   マッチング対象の制度について、基本スコアを100点として計算を開始する。
2.  **足切り（ハードフィルタ）の維持**
    *   制度の必須条件（年齢、都道府県、子どもの有無など）を明確に満たさない場合は、スコア計算を行わず、マッチング対象から除外（スキップ）する。
3.  **「わからない」「未入力」による減点**
    *   プロフィール情報が「わからない」「未入力」である場合、または所得帯の幅によって「対象外の可能性がある」場合は、対象外とは断定せず、項目に応じた減点を行う。
4.  **status の自動ダウングレード**
    *   一度でも減点が発生した場合（`warnings` が追加された場合）、その制度の `status` を `eligible` から `possible` にダウングレードする。
5.  **地域判定の精緻化**
    *   Role A で追加された `city` (市区町村) および `ward` (区) を判定ロジックに組み込む。

---

## 2. 減点ロジックの詳細

合致しない可能性が高い項目、または確認の重要度が高い項目ほど大幅な減点を行う。

### 2.1 地域条件（都道府県・市区町村・区）
地域指定がある制度において、より詳細な階層で不一致または不明な場合に減点する。

| 項目 | 条件 | 減点スコア | warning メッセージ |
| :--- | :--- | :--- | :--- |
| 都道府県 | **不一致** | **除外** | - |
| 市区町村 | 指定があるが、プロフィールの `city` が未入力 | -20 | 市区町村単位の対象条件の確認が必要です |
| 市区町村 | 指定があり、プロフィールの `city` が一致しない | **除外** | - |
| 区 | 指定があるが、プロフィールの `ward` が未入力 | -10 | 区単位の対象条件の確認が必要です |
| 区 | 指定があり、プロフィールの `ward` が一致しない | **除外** | - |

### 2.2 年齢条件
| 項目 | 条件 | 減点スコア | warning メッセージ |
| :--- | :--- | :--- | :--- |
| 年齢 | 範囲外（明確な不一致） | **除外** | - |
| 年齢 | プロフィールの生年月日が未入力 | -20 | 年齢制限がある制度です。生年月日の登録を確認してください |

### 2.3 所得・税条件
所得制限は、ユーザーが選択した「所得帯」の上限値と、制度の閾値を比較するため、境界線付近では常に不確実性が残る。

| 項目 | 条件 | 減点スコア | warning メッセージ |
| :--- | :--- | :--- | :--- |
| 所得上限 | プロフィールの所得帯上限が、制度の閾値を超えている | **除外** | - |
| 所得上限 | プロフィールの所得帯上限が閾値以下だが、**閾値に近い**（例：閾値の80%以上） | -15 | 所得制限の境界線付近です。正確な所得による確認が必要です |
| 所得上限 | プロフィールの所得情報が「未入力」または「不明」 | -20 | 所得制限がある制度です。所得情報の確認が必要です |
| 非課税世帯 | 制度が必須としているが、プロフィールが「わからない」 | -20 | 住民税非課税世帯であるか確認が必要です |
| 非課税世帯 | 制度が必須としているが、プロフィールが「いいえ」 | **除外** | - |

### 2.4 世帯・属性条件（子ども・ひとり親・性別）
| 項目 | 条件 | 減点スコア | warning メッセージ |
| :--- | :--- | :--- | :--- |
| 子ども有無 | 制度が必須としているが、プロフィールが「なし」 | **除外** | - |
| ひとり親 | 制度が必須としているが、プロフィールが「いいえ」 | **除外** | - |
| ひとり親 | 制度が必須としているが、プロフィールが「その他・不明」 | -15 | ひとり親世帯等の対象条件の確認が必要です |
| 性別 | 制度が指定しているが、プロフィールが「回答しない」 | -10 | 性別による対象制限の確認が必要です |
| 性別 | 制度が指定しているが、プロフィールが不一致 | **除外** | - |

## 3. ステータス判定フロー

各制度のスコア計算終了後、最終的なレスポンス値を決定する。

```python
score = 100
warnings = []
status = "eligible"

# 各判定処理を実行（例：所得判定）
if some_condition_is_ambiguous:
    score -= 20
    warnings.append("...")

# 最終判定
if warnings:
    status = "possible"

# スコアが0を下回らないように補正
score = max(score, 0)
```

## 4. 特筆事項：大幅な減点の基準

「合致しない可能性が高い項目」について大幅な減点（-20点）を適用する基準は以下の通り。

1.  **制度の根幹をなす条件が不明な場合**
    *   所得制限がある制度で所得が不明な場合や、地域限定の制度で地域が不明な場合。これらは受給可否に直結するため、ユーザーに強い注意を促す意味で -20点 とする。
2.  **不一致のリスクが客観的に高い場合**
    *   特定の市区町村限定の制度に対し、市区町村が入力されていない場合。広域の制度よりも対象者が限定されるため、不一致である確率が高く、-20点 とする。

## 5. 実装計画

減点方式への刷新に向け、以下のファイルおよび関数を修正・実装する。

### 5.1 app/services/matching_service.py
ロジックの中核となる `calculate_match_score` 関数を全面的にリファクタリングする。

*   **`calculate_match_score(profile, program, condition)` の刷新**:
    *   **初期化**: `score = 100`, `reasons = []`, `warnings = []`, `status = "eligible"` で開始する。
    *   **足切り（ハードフィルタ）の実装**:
        *   不一致時に `return None` するロジックを優先して配置する。
        *   都道府県不一致、市区町村・区の不一致（プロフィールに入力がある場合）、年齢範囲外、所得上限超過、必須属性（子、ひとり親、非課税）の明確な否定、性別不一致を判定する。
    *   **減点ロジックの実装**:
        *   本ドキュメントの「2. 減点ロジックの詳細」に基づき、情報不足や境界線判定による減点（-10〜-20点）と `warnings` へのメッセージ追加を行う。
        *   地域判定に `profile.city` および `profile.ward` を追加し、制度側で指定があるがプロフィール側が空の場合に減点する。
    *   **ステータス確定**: `warnings` が存在する場合、`status` を `possible` に変更する。
    *   **スコア補正**: `max(0, score)` で負数を防止する。
*   **`calculate_age` の維持**:
    *   既存の年齢計算ロジックはそのまま利用する。

### 5.2 app/schemas/match.py
*   **`MatchResultResponse` の確認**:
    *   既存の `score`, `status`, `reasons`, `warnings` フィールドが減点方式の出力と合致しているか再確認する（基本的には変更不要の想定）。

### 5.3 app/repositories/program_repository.py
*   **`list_programs_with_conditions` の確認**:
    *   マッチング対象となる全制度と条件を効率的に取得できているか確認する（現状維持で問題ないことを確認する）。

### 5.4 動作確認の計画
